Open weaknesses, vulnerabilities and improvements

Scope: UTILS/CustomAuthenticators (providers, MBean definitions, build), UTILS/CommonLib (osb-commons) and the XML schemas of the OSB configuration project. The configuration data of a specific installation (policies, mappings, keys, secrets) is out of scope: see the sample project in osb/OAUTH2 for a reference configuration.

H-04HighBuild res/BeanInfoBinder-body.template:16, 22, 58-62; CustomAuthenticator.java:233-241 If the reordering of the BeanInfo descriptors fails (MDF not found in the jar, XPath engine not available on JDK 17 without --add-exports, parse error), the exception is printed and an array of nulls is returned. init() calls getName() on null, catches the NPE and throws ProviderInitializationException (MBeanInfo load error): the realm cannot be loaded and the server fails at boot. M-03MediumProviders CustomAuthenticator.java:785; CustomOutboundAuthenticator.java:662, 682 Templates are resolved inside the script text before evaluation; for String claims and parameters the JavaScript escaping is applied before resolution, so the substituted values are not escaped. A value containing ' or \ (a secret, a header value, a context variable) breaks the evaluation or injects code into an engine with full Java access. Escape after resolution, or better pass values as script bindings; for String types skip the script engine entirely and use the resolved value.
M-04MediumProviders CustomOutboundAuthenticator.java:438, 490, 494, 605-608, 731, 748; CustomAuthenticator.java:659 XPath expressions are built by concatenating values. Most come from configuration, but the secure header key (438) is resolved from templates that can contain request-derived variables (${http.header.*}, ${osb.metadata.*}, ${osb.context.*}). A crafted value such as x' or '1'='1 selects the first remote user of HeaderSecrets and its secret is sent to the backend; names with an apostrophe break the lookup. Compare in Java as in reverseTranslateResource, or reject values containing quotes; document which variables are safe in secret keys.
M-05MediumProviders / osb-commons CustomInboundAuthenticator.java:706-760; CommonLib/.../jwt/JWTCache.java:42-43, 71-74, 101-104 A kid not found in cache triggers a JWKS download on every request; caches have no size limit, entries are evicted only on lookup of the same key, and tokens are used until the second of their expiry. Tokens with random kid (unauthenticated) turn every request into a call to the identity provider; tokens close to expiry fail at the backend. Rate-limit JWKS refreshes per URL and cache negative results briefly; add an expiry margin (30-60 s) and a size bound; meanwhile configure token_cache_ttl a few minutes below the token lifetime.
M-06MediumProviders CustomAuthenticator.java:552-649, 629-633; CommonLib/.../XMLUtils.java:83-96, 88 In the default mode an invalid resource is used anyway; the negative outcome is not cached, so the schema is compiled and all errors are logged at every request. Schema compilation allows downloading remote imports (setCompileDownloadUrls). The comment says WARN while the code logs ERROR. A wrong deployment produces a flood of log lines and CPU load and runs with partially valid policies; outbound network access from schema compilation. Cache the negative footprint (log once per version), disable URL downloads, cache the compiled SchemaTypeLoader; consider strict mode for security-relevant resources (inbound policies, mappings).

M-20MediumProviders / osb-commons CustomAuthenticator.java:292-305; CommonLib/.../SecurityUtils.java:80-98 When KERBEROS_CONFIGURATION is not empty (the providers no longer call configKerberos with an empty configuration), configKerberos sets the JVM-wide properties java.security.krb5.conf (one static temporary file shared by all instances) and javax.security.auth.useSubjectCredsOnly=false, without checking whether a configuration is already set. M-21MediumProviders / osb-commons CustomAuthenticator.java:262, 785; CommonLib/.../JavaUtils.java:65-76 One ScriptEngine per provider instance is shared by all execute threads and eval(String) runs on its default context and global scope; neither Nashorn nor the bundled Rhino engine declares itself multithreaded. M-22MediumProviders / osb-commons CommonLib/.../WLSUtils.java:160-177; CustomAuthenticator.java:455, 461 Inbound custom request headers are injected by replacing the first header with exactly the same name (case-sensitive) or by appending a new one; when the resolved value is empty the header is skipped. WebLogic getHeader() compares names case-insensitively and returns the first match. A client that sends the header itself with a different case (e.g. x-auth-user), or twice, or when the provider value is empty, makes the proxy pipeline read the client value instead of the one asserted by the provider: any trust placed in injected headers can be spoofed. Remove every occurrence of the header (case-insensitive) and then add the provider value once; remove the client header also when the resolved value is empty; document which injected headers the proxies may trust.
