Open weaknesses, vulnerabilities and improvements

Scope: UTILS/CustomAuthenticators (providers, MBean definitions, build), UTILS/CommonLib (osb-commons) and the XML schemas of the OSB configuration project. The configuration data of a specific installation (policies, mappings, keys, secrets) is out of scope: see the sample project in osb/OAUTH2 for a reference configuration.

H-01HighProviders CustomAuthenticator.java:217, 241, 255, 266, 286, 298; CustomOutboundAuthenticator.java:128-131, 139-141 Every initialization error, and a second outbound provider, call System.exit(0). The outbound registry is never cleared in shutdown(). A configuration mistake or an environment problem (e.g. Kerberos temp file, script engine) silently terminates Admin/Managed servers with exit code 0. A realm restart in the same JVM (supported since 12.2.1) re-initializes the outbound provider, finds the old registry entry and stops the server. Throw ProviderInitializationException/RuntimeException so WebLogic reports the failed provider; clear the registry entry in shutdown(); name the conflicting providers in the message.
H-02Highosb-commons CommonLib/src/org/falpi/utils/HttpUtils.java:249-251; CustomAuthenticator.java:842-843 HttpClient is built with connect timeout and connection-request timeout only; no socket (read) timeout. REQUESTS_READ_TIMEOUT is passed as connection-request timeout, which has no effect with a fresh pool per call. An identity provider, JWKS endpoint or proxy that accepts the connection but does not answer blocks the execute thread forever: stuck threads, server in WARNING/FAILED, all authenticated OSB traffic affected. Add setSocketTimeout(read*1000); consider a hard overall timeout; reject 0 (infinite) for both timeouts.
H-03Highosb-commons CommonLib/.../HttpUtils.java:457-460; MBean REQUESTS_SSL_VERIFY With REQUESTS_SSL_VERIFY=DISABLE the client trusts every certificate and host name (config). Inbound: a man in the middle can serve a forged JWKS and every forged JWT is accepted. Outbound: client secrets and client assertions are disclosed and access tokens can be replaced. Allow DISABLE only with an explicit WARN at every request, or replace it with a configurable trust store; never use it in production.
H-04HighBuild res/BeanInfoBinder-body.template:16, 22, 58-62; CustomAuthenticator.java:233-241 If the reordering of the BeanInfo descriptors fails (MDF not found in the jar, XPath engine not available on JDK 17 without --add-exports, parse error), the exception is printed and an array of nulls is returned. init() calls getName() on null, catches the NPE and calls System.exit(0): the server stops at boot. Fill the array with the unordered descriptors before reordering and replace it only on success; null checks; close the stream.
M-01MediumProviders CustomInboundAuthenticator.java:176-183; CustomOutboundAuthenticator.java:212-221; CustomAuthenticator.java:1000-1010 cleanThread() is not in a finally block, and assumes the thread-locals exist. After every failed assertion or outbound error the thread-locals keep the request objects, the token and (outbound) client_secret/client_assertion on the pooled WebLogic thread until its next use by the provider. Wrap the implementation in try/finally and make cleanThread() null-safe.
M-02MediumProviders CustomAuthenticator.java:456, 479; CustomOutboundAuthenticator.java:845, 856 DEBUG logs every header added to requests and responses with its value, including translated secure headers; TRACE logs the full token request (client_secret or client_assertion) and the token response (access_token). Secrets and bearer tokens end up in the server .out files, which are usually less protected than the secrets themselves. Mask secure headers and the sensitive form parameters (log only names or a fingerprint); keep TRACE output free of credentials.
M-03MediumProviders CustomAuthenticator.java:785; CustomOutboundAuthenticator.java:657, 677 Templates are resolved inside the script text before evaluation; for String claims and parameters the JavaScript escaping is applied before resolution, so the substituted values are not escaped. A value containing ' or \ (a secret, a header value, a context variable) breaks the evaluation or injects code into an engine with full Java access. Escape after resolution, or better pass values as script bindings; for String types skip the script engine entirely and use the resolved value.
M-04MediumProviders CustomOutboundAuthenticator.java:433, 485, 489, 600-603, 726, 743; CustomAuthenticator.java:659 XPath expressions are built by concatenating values. Most come from configuration, but the secure header key (433) is resolved from templates that can contain request-derived variables (${http.header.*}, ${osb.metadata.*}, ${osb.context.*}). A crafted value such as x' or '1'='1 selects the first remote user of HeaderSecrets and its secret is sent to the backend; names with an apostrophe break the lookup. Compare in Java as in reverseTranslateResource, or reject values containing quotes; document which variables are safe in secret keys.
M-05MediumProviders / osb-commons CustomInboundAuthenticator.java:701-755; CommonLib/.../jwt/JWTCache.java:42-43, 71-74, 101-104 A kid not found in cache triggers a JWKS download on every request; caches have no size limit, entries are evicted only on lookup of the same key, and tokens are used until the second of their expiry. Tokens with random kid (unauthenticated) turn every request into a call to the identity provider; tokens close to expiry fail at the backend. Rate-limit JWKS refreshes per URL and cache negative results briefly; add an expiry margin (30-60 s) and a size bound; meanwhile configure token_cache_ttl a few minutes below the token lifetime.
M-06MediumProviders CustomAuthenticator.java:552-649, 629-633; CommonLib/.../XMLUtils.java:83-96, 88 In the default mode an invalid resource is used anyway; the negative outcome is not cached, so the schema is compiled and all errors are logged at every request. Schema compilation allows downloading remote imports (setCompileDownloadUrls). The comment says WARN while the code logs ERROR. A wrong deployment produces a flood of log lines and CPU load and runs with partially valid policies; outbound network access from schema compilation. Cache the negative footprint (log once per version), disable URL downloads, cache the compiled SchemaTypeLoader; consider strict mode for security-relevant resources (inbound policies, mappings).
M-07MediumProviders CustomInboundAuthenticator.java:845-850 ${http.content.body} reads the servlet input stream of the inbound request. If used in LOGGING_INFO, DEBUGGING_PROPERTIES or custom headers the proxy service receives an empty body. M-13MediumProviders CustomOutboundAuthenticator.java:875-881 new JSONObject(body) inside the catch is not protected. M-14MediumProviders CustomOutboundAuthenticator.java (all TransportExceptions) Errors are raised without error code, so OSB maps them to OSB-380000 (transport error). OSB applies retries and failover of the business service; with an offline duration configured, an identity provider problem (e.g. expired secret) can take the backend URL offline. Evaluate a dedicated error code (or OSB-380001 for non-retriable errors) and document the behaviour per business service.
